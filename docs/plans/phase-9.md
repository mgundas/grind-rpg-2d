# Phase 9 — The wider world (plan)

Scope: `GAME_DESIGN.md` §3.1 (all maps), §12 Phase 9 (all maps, channels CH1–CH4
with picker, monsters/items to level 60, Spider Cave instanced dungeon with a
boss, mounts, teleporter NPC between maps).

## 1. What already exists that this phase builds on

- **2 maps live**: `map_ember_village` (80×80) + `map_ember_fields` (160×160),
  generated by `packages/data/src/generate-maps.ts`, committed as Tiled JSON and
  parsed identically on both sides (`parseTiledMap`, D11). Adding a map touches
  `shared/constants.ts` (`MAP_IDS`), `maps/policies.json`, the generator, the
  server `server.ts` registrations + `maps/mapRegistry.ts`, the client
  `Preload.ts` imports + `world/mapKeys.ts`, `MAP_LABELS`, and tests.
- **Rooms**: one `MapRoom` (~6.4k lines) registered per map name; room name ==
  map id. `maxClients = 200`, 20 Hz tick, StateView interest 850/900 px, stones
  deliberately unfiltered (D71).
- **Warps**: server saves the destination row, issues a single-use 30 s token
  bound to account+character+map, reserves a seat, client consumes the
  reservation and restarts the World scene. Reused by return scrolls and death.
- **Channels**: only the `characters.channel` column + admin grouping; no
  matchmaking key, no picker, warps do not preserve a channel.
- **Parties**: room-scoped and dropped on warp (D74 explicitly defers
  cross-map parties to Phase 9). Guild/friend/whisper routing is already
  process-wide.
- **Content ceilings**: monsters 1–15, items `levelReq` ≤ 30 with T3/T4 shipped
  but unobtainable (D72), skills unlock 5–30, one stone type, 4 spawn groups.
  `MAX_LEVEL` is already 99.
- **Speed**: `WALK_SPEED = 200`, shared `stepMover`, shared
  `moveSpeedMultiplier` for equipment bonuses, predictor already accepts a
  multiplier. No mount concept and no mount field on `PlayerState`.
- **NPCs**: `NPC_KINDS = shop | warehouse | blacksmith`; no teleporter.
- **Policies**: Fields is `pvpAllowed: true` as a deliberate Phase-8 stand-in
  (D73).
- **World map UI**: 2-column placeholder layout.
- **Verified library API**: `@colyseus/core@0.17.56` exposes
  `defineRoom(X).filterBy([...])`, and `getFilterOptions` copies matching join
  options into the room's filter/metadata
  (`apps/server/node_modules/@colyseus/core/build/matchmaker/RegisteredHandler.{d.ts,cjs}`).
  Channels therefore use `filterBy(['channel'])` + `setMetadata({channel})`.

## 4. Hard systems

### Channels (networking)
`defineRoom(MapRoom).filterBy(['channel'])`, every reservation (join, warp,
teleport, channel switch) carries `channel`, warp tokens bind it, and
`setMetadata({ mapId, channel })` keeps the lobby sane. A full channel rejects
with `channel_full` instead of silently overfilling. A stale persisted channel
is clamped to 1. Switching is throttled by the existing 2 s warp cooldown.

### Dungeon instancing
A separate room name (`map_spider_cave`) with `filterBy(['partyId'])`; the
leader creates the instance, members join by party id, solo entry is rejected.
Leadership passes on leader leave, the instance stays while any member is
inside, and it disposes when empty. Boss leashes/heals on wipe, loot uses the
existing ownership path, and death inside reuses the existing town-save rule.

### Cross-map party
The registry moves to a process-wide service keyed by party id; rooms subscribe
member snapshots per tick. Warping no longer drops the party. XP/loot stay
1500 px local, party chat keeps working through the social bus, and offline or
kicked members are pruned on the next snapshot.

### PvP on neutral maps
The `canAttackPlayer` matrix is unchanged; only policy flags change (Fields
becomes non-PvP, Valley/Forest become neutral PvP, villages/highlands stay
safe/kingdom-only). Party/guild exclusions already protect cross-kingdom groups.

### Mounts
Speed is `WALK_SPEED * moveSpeedMultiplier(equip) * MOUNT_SPEED_MULT` in shared
code so predictor and server agree bit-exactly. Mounting while casting, trading,
dead or inside the dungeon is rejected; warp, dungeon entry, attack and death
dismount server-side. The client updates the predictor multiplier from the
`mounted` state change.

### Teleporter economy
A flat fee per hop (data-driven by distance tier), deducted in the same
transaction as the destination save; insufficient gold returns `teleportError`.
Dungeon entry is free.

## 7. Risks

- **R1 — Ember Fields vs the final map list**: renaming breaks saved characters.
  Keep `map_ember_fields` and retheme it as the Ember Highlands (DECISIONS).
- **R2 — MapRoom is already huge**: new systems go in new modules; MapRoom only
  gains thin handler calls.
- **R3 — Preload with 11 maps**: lazy-load tilemap JSON per map on warp if the
  startup cost is measurable.
- **R4 — `filterBy` typo silently disables filtering**: a room test asserts two
  channels land in different rooms.
- **R5 — Abandoned dungeon instances**: dispose on empty plus an idle sweep,
  verified by E2E.
- **R6 — 1→60 balance is untested design space**: gate with the balance sim and
  tune data only.
- **R7 — Mount speed desync**: one shared multiplier function; a 600-tick
  predictor/server agreement test.
