# Phase 1 — Walk together: Report

Built against `docs/plans/phase-1.md`. This report covers the second phase gate: all four commands, a fresh `@reviewer` pass, fixes for every IMPORTANT finding, the full-stack acceptance run (normal and 150 ms simulated latency), and the remaining MINOR findings listed in `PROGRESS.md` → “Phase 1 — Known issues”.

## What was built

- **Shared deterministic simulation**: `direction.ts` (8 directions, 4 facings, `INV_SQRT2` literal), `tiled.ts` (strict Zod Tiled JSON reader), `collision.ts` (body-aware grid, nearest-walkable), `movement.ts` (`stepMover`, axis-separated collide-and-slide), `pathfinding.ts` (deterministic A*, no corner slicing, LOS + string-pulling), `protocol.ts` (Zod input/chat schemas, warp payload), `chat.ts` (pure range filter).
- **Generated maps**: seeded Ember Village (80×80: plaza, roads, river + bridge, houses, fences, tree border, east warp) and Ember Fields (160×160: clearings, groves, rocks, mob/stone zones, west warp), committed as Tiled JSON and regenerated by `pnpm generate:maps`; invariant tests cover spawn walkability, borders, connectivity and cross-map warp targets.
- **Server**: two map rooms (`map_ember_village`, `map_ember_fields`) from one `MapRoom`, 20 Hz authoritative tick (one intent per tick, 3-tick packet-loss grace, click-to-move path following), Zod-validated inputs/chat, StateView interest management (850/900 px hysteresis at 4 Hz), ranged chat + 1 s cooldown, seat-reservation warps with single-use spawn tokens and arrival cooldown, `SIMULATE_LATENCY_MS`.
- **Client**: Colyseus session + guest join panel, real Tiled map rendering with y-sorted tall decor and camera follow, WASD/arrow + hold-to-steer + click-to-move with client prediction and replay reconciliation, 100 ms buffered interpolation for remote players, chat log + bubbles + focus handling, F3 debug overlay (FPS, ping, ack, snaps, visible players), fade-out/in warp.

## Reviewer findings fixed in this pass

- **Warp failure loop / token leak**: a failed reservation now sets the normal 2 s warp cooldown; expired warp tokens are pruned on issue, a wrong-map token is rejected without being burned, and a client that ignores the `warp` message is disconnected after 2 s.
- **Interest management was a no-op on the wire**: the installed `@colyseus/schema` ignores `view: true` inside `@type()`; the collection now uses the separate `@view()` decorator, and the view is created before the player is added. New wire-level tests assert `client.state.players`, not only `serverClient.view`.
- **Remote interpolation dropped burst samples**: patches sharing one receipt timestamp now replace the latest sample instead of being discarded; added a burst test.
- **Predictor false snaps**: reconciliation now measures error against the prediction, not the still-decaying visual offset; added a two-correction regression test.
- **A* hostile-client budget**: repeated unreachable goals are cached for 1 s and retargets are limited to one per 100 ms, without changing the per-tick recompute that keeps client replay exact.
- **Grace ticks**: the dead `SERVER_TICK_GRACE_TICKS` is now implemented (3 ticks); an explicit `none` still stops immediately.
- **Y-sorting**: tall `decor` tiles are rendered as individual images with `depth = (row + 1) * tileSize`, so players draw behind/in front of trees by row; `ground` and `above` remain tile layers.
- **150 ms latency crash**: `server.simulateLatency()` was called before `listen()`, when the transport is undefined. It now runs in the `listen()` callback; the 150 ms run boots and passes.
- **Test gaps**: added protocol schema tests, A* corner/unreachable tests, a one-tile-door movement test, warp-token lifecycle tests, input-queue drop and path-budget tests, chat cooldown boundary, and wire-level interest tests. The e2e now consumes the warp reservation and verifies the arrival map/spawn.

```sh

node scripts/verify-phase1-e2e.mjs   # needs pnpm dev running
```

```powershell

pnpm dev
```

The database is not used by Phase 1 gameplay; if `POSTGRES_HOST` points at an unreachable machine, `/api/health` reports `db: "unavailable"` and the game still runs.

## Manual acceptance test (exact steps)

1. **Join and see each other.** Run `pnpm dev`. Open http://localhost:5173 in two browser tabs/windows. Join as different names/kingdoms. Each tab should show its own character and the other player standing on the generated village tiles.
2. **Two tabs move smoothly, no jitter.** In tab A, walk with WASD, arrows, click-to-move and click-and-hold-to-steer for ~30 s. Tab B should show A moving smoothly (no teleporting/stutter). Press F3 in both: check sane FPS, ping, `lastSeq` increasing, `snaps` staying 0 while walking straight, and `visiblePlayers` matching the tabs.
3. **Collisions are identical.** Walk into a house, the river (without the bridge), a fence and a tree in both tabs. Motion must stop at the same place in both. Cross the river via the three-tile bridge; both tabs must pass.
4. **Chat and bubbles.** Press Enter, type a message containing W/A/S/D and spaces, press Enter. The text must appear (not move the character) in the chat log, and a bubble must appear above the sender in both tabs. Walk more than ~900 px away and send again: the far tab must not receive it.
5. **Warp both directions.** Walk to the east exit of Ember Village. The screen fades out, the client leaves the village room, consumes the reservation, rebuilds the fields map and fades in at the fields spawn. Walk west from the fields spawn to return to the village spawn. Confirm F3 shows the new map id.
6. **150 ms latency feels smooth.** Stop the stack, set `SIMULATE_LATENCY_MS=150` (or PowerShell above), run `pnpm dev`. Join two tabs. The local character must still respond immediately (prediction), remotes must interpolate smoothly, and F3 should show ~300 ms RTT with no snap spam while walking straight.
7. **Backgrounded tab.** Hide a tab for ~10 s, then return. Movement should resume without a large teleport; F3 `snaps` should stay low.
8. **Y-sorting.** Stand directly north of a tree/fence and then directly south of it. The player sprite should draw behind the tree in the first case and in front in the second (placeholder art is a flat tile, so the depth order is what changes).

## Known issues

The remaining MINOR reviewer findings are recorded in `PROGRESS.md` → “Phase 1 — Known issues (minor, deferred)”. The most user-visible ones:

- Browser look-and-feel (smooth remote motion, bubbles, fade, 150 ms feel) was verified at the state/netcode level, not with browser automation; the manual steps above are the human pass.
- All guest joins use the exact map spawn, so two tabs overlap until Phase 2 adds persistence/character positions.
- Chat range (900 px) is slightly wider than the interest add radius (850 px), so a player just inside chat range may not have a remote sprite/bubble.
- A* still recomputes per path tick for exact replay; the new failure cache/retarget limit bounds hostile use, and path caching is a Phase 3+ optimisation.
- Local chat only; shout/whisper/scramble and chat tabs are Phase 8.
- No reconnection tokens: an unexpected disconnect returns to the join panel and rejoins at the current map's spawn.
