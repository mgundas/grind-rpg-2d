# Phase 1 — Walk together: Report

Built against `docs/plans/phase-1.md`; one `@architect` consult for the netcode system (as AGENTS.md requires) and one `@reviewer` pass at the end. Reviewer findings were fixed (keyboard capture, input batching speed, warp-token spawn authority, reconnect map state, warp-failure race, missing parity/burst tests, doc drift).

## What was built

- **Shared deterministic simulation**: `direction.ts` (8 directions, 4 facings, `INV_SQRT2` literal), `tiled.ts` (strict Zod Tiled JSON reader), `collision.ts` (body-aware grid, nearest-walkable), `movement.ts` (`stepMover`, axis-separated collide-and-slide), `pathfinding.ts` (deterministic A*, no corner slicing, LOS + string-pulling), `protocol.ts` (Zod input/chat schemas, warp payload), `chat.ts` (pure range filter).
- **Generated maps**: seeded `Ember Village` (80×80: plaza, roads, river + bridge, houses, tree border, east warp) and `Ember Fields` (160×160: clearings, groves, rocks, mob/stone zones, west warp), committed as Tiled JSON and generated by `pnpm generate:maps`; invariant tests cover spawn walkability, borders, connectivity and cross-map warp targets.
- **Server**: two map rooms (`map_ember_village`, `map_ember_fields`) from one `MapRoom`, 20 Hz authoritative tick (one intent per tick, click-to-move path following), Zod-validated inputs/chat, StateView interest management (850/900 px hysteresis at 4 Hz), ranged chat + 1 s cooldown, seat-reservation warps with single-use spawn tokens and arrival cooldown, `SIMULATE_LATENCY_MS`.
- **Client**: Colyseus session + guest join panel, real Tiled map rendering with y-sorting and camera follow, WASD/arrow + hold-to-steer + click-to-move with client prediction and replay reconciliation, 100 ms buffered interpolation for remote players, chat log + bubbles + focus handling, F3 debug overlay (FPS, ping, ack, snaps, visible players), fade-out/in warp.

## Verification

Green: `pnpm typecheck`, `pnpm lint`, `pnpm format:check`, `pnpm test` (**131 tests**, 12 files), `pnpm build`, server smoke (`--dist`), and the committed SDK acceptance script against `pnpm dev`:

`SIMULATE_LATENCY_MS=150 pnpm dev` is wired through `server.simulateLatency()` (both directions, so F3 shows ~300 ms RTT).

### Manual checks (browser visuals)

1. `pnpm dev`, open http://localhost:5173 twice. Join with different names/kingdoms.
2. Both characters must stand on the generated village tiles and see each other walk smoothly (WASD, arrows, click-to-move, hold-to-steer); F3 shows sane fps/ping and `snaps` stays 0 while walking straight.
3. Walk into houses/water/trees — motion stops identically in both tabs; cross the bridge.
4. Type in chat (Enter): letters including W/A/S/D and spaces must appear; bubbles show above both heads; walk >900 px apart and messages stop.
5. Take the east exit in the village → fade → fields; take the west exit in the fields → fade → village.
6. Restart the server with `SIMULATE_LATENCY_MS=150` in `.env`; own character stays instant, remotes stay smooth.
7. Hide the tab for ~10 s, return: movement resumes without teleporting.

## Known issues

- Visual/browser checks above were verified headlessly only at the network/state level (no browser automation in this environment); the acceptance matrix's look-and-feel items remain a human pass.
- A* is recomputed per path tick while auto-walking (replay exactness); fine for Phase-1 populations, to be optimized with path caching/spatial hashing in Phase 3+.
- Local chat only; shout/whisper/scramble and chat tabs are Phase 8.
- No reconnection tokens: an unexpected disconnect returns to the join panel and rejoins at the current map's spawn (map is remembered).
- No auth/character data yet; guest names are not unique and spawn positions are server-issued only (Phase 2 adds accounts and persistence).
- The `above` layer exists but holds no tiles yet, so tall-decoration y-sorting is only applied to entities until real art/props arrive.
