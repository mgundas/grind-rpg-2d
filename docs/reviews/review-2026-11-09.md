# Jade Throne — Full Codebase Review (Phases 0–7 + Phase 8 tasks 1–17)

Method: read `AGENTS.md`, `PROGRESS.md`, `DECISIONS.md` and `GAME_DESIGN.md` §§11–12, then five parallel read-only area reviews (`packages/shared`, `apps/server`, `apps/client`, `apps/admin`, `packages/data`/scripts/config). No files changed.

## Critical (must fix before continuing)

**1. Offline admin grant/remove can clobber a live inventory.**
`apps/server/src/admin/adminMutations.ts:272-293,359-380` — `grantItemOffline`/`removeItemOffline` load inventory, _then_ check `isOnline`, _then_ plan and commit outside any lock. A player joining between the check and the commit gets their live in-memory inventory overwritten by a stale-snapshot DB write (item loss, possible duplication). Why it matters: this is the only true data-loss race found. Fix: re-check `isOnline` immediately before `applyItemTransaction` and reroute to the live path on conflict (mirrors the `updateCharacterOffline` row-locked pattern at `:168-180`).

**2. Dash destination applied without a walkability check (verify first).**
`apps/server/src/rooms/MapRoom.ts:5379` assigns `outcome.dash.destination` directly to mover/state. If shared `resolveSkillCast` doesn't clamp to walkable tiles, dash skills teleport through walls — a movement cheat. Fix: one read of the shared resolver; if unclamped, add a `nearestWalkable` clamp in `applySkillOutcome` plus a test.

**3. Death XP loss is not promptly persisted.**
`MapRoom.ts:2846` (`handlePlayerDeath`) sets `dirty=true` but never enqueues a save, and autosave (`:2185`) explicitly skips dead players. A crash while the victim is dead rolls back the 2% XP loss. Fix: call the save enqueue at the end of `handlePlayerDeath`.

**4. Unknown monster `typeId` crashes the whole scene.**
`apps/client/src/scenes/World.ts:1605,1686` — `getMonster()` throws on unknown id, called unguarded in `createMonsterVisual` and per-frame in `updateMonsters`. With Phase 7 catalog hot-reload, server/client skew is now plausible and kills the render loop. Fix: `try/catch` with a fallback sprite, same pattern as `createGroundVisual` (`:1165`).

**5. Admin logout doesn't reliably clear the Secure cookie.**
`apps/server/src/http/adminCookie.ts:61-63` — `clearAdminCookie` omits `secure`/`sameSite`, but `setAdminCookie` (`:46-59`) sets `secure:true` in prod, so `jt_admin` can survive logout and keep `/colyseus` accessible until token expiry. Fix: mirror the flags in `clearAdminCookie`.

## Important (fix during the next phase)

**6. Dead players can allocate stats, change doctrine, spend skill points.**
`MapRoom.ts:5524` (`allocateStat`) checks `warping` but not `dead`; `chooseDoctrine` (`:3748`) and `upgradeSkill` (`:3770`) rely solely on `inventoryClosed`. Every item/guild path has the guard. Fix: add `dead`/`warping` checks, ideally centralized in `runSkillCommand` (which also fixes 7).

**7. `runSkillCommand` uses a stale runtime capture.**
`MapRoom.ts:3712` closes over the schedule-time `runtime`; `runItemCommand` (`:2959`), `runGuildCommand` (`:4144`), `runFriendCommand` (`:4032`) all re-fetch via `runtimes.get`. Safe today only by accident. Fix: re-fetch inside `run`.

**8. PvP-mode toggle persist is fire-and-forget.**
`MapRoom.ts:3976` (`void persist(...)`) — two rapid toggles can commit out of order while each callback mirrors its own value. Fix: route through the save chain or ignore stale responses.

**9. Full-stack merge returns silent `ok:true` no-op.**
`packages/shared/src/inventory.ts:347-356` — `space === 0` returns success with nothing moved; client thinks the drag worked. Fix: return `{ok:false, code:"stack_full"}` (new code + protocol entry).

**10. `normalizeInventory` can persist permanently-overlapping state.**
`inventory.ts:566-571` — a "truly full" grid keeps the overlapping item in place with `repaired:true`, re-repaired on every load. Fix: spill to an overflow list/staging, emit a metric, never persist overlap.

**11. `buildCatalog` never validates `monster.dropTableId`.**
`packages/data/src/monsters.ts:92`, `catalog.ts:179-181` — unlike stones/spawnGroups, no `{hasDropTable}` ref is threaded in. A bad admin override passes validation and the room silently falls back to `?? []` (`MapRoom.ts:2732`): monsters drop nothing with no error. Fix: same pattern as `buildStones`; loud log on missing tables.

**12. Auto-walk pathfinding bypasses the shared A\* budget.**
`MapRoom.ts:6116` (`autoWalkStep`) calls `findPath` every 250 ms per chaser plus every tick on empty paths; monster repaths share `MAX_ASTAR_PER_TICK` (`:5588`) but chasers are unbounded. Fix: route auto-walk through `takeAstar`.

**13. Same-goal path intents recompute A\* every tick.**
`MapRoom.ts:6172` (`applyPathIntent`) rate-limits only retargets; a hostile client streaming `path` at 30 msg/s forces an A\* per tick. Fix: cache the path per goal tile until the player changes tile.

**14. Line-skill corridor end-cap math is wrong.**
`packages/shared/src/combat.ts:176-179` (`findLineTargets`) — the beyond-end test adds _squared_ quantities (`distSq + halfWidthSq` instead of `(len+hw)²`), and targets behind `origin` within `halfWidth` are wrongly accepted. Fix: return projection `t` from the segment test, accept `t∈[0,1]` with `distSq ≤ hw²`; add the missing `findLineTargets`/`findCircleTargets` tests (only arc is covered).

**15. Move-speed formula is duplicated client-side.**
`World.ts:393-402` sums bonuses and calls `setSpeedMultiplier` every frame while `state/predictor.ts:221,232,241` multiplies `WALK_SPEED`. Any divergence (cap, stacking) causes constant reconcile snaps. Fix: one shared function, unit-tested, called from both.

**16. Drop expiry mixes wall-clock and server-clock.**
`World.ts:1225-1235` compares server `despawnAtMs`/`ownerUntilMs` against `Date.now()` while interpolation correctly uses receipt time. Clock skew makes drops vanish early or linger. Fix: track a server-clock offset or age drops by receipt time.

**17. In-game GM commands likely bypass `admin_log`.**
`MapRoom.ts:1670-1687` executes `/item`-style commands via `adminGrantItem` etc. with no audit write; auditing lives only in HTTP routes, while the spec says every admin action is logged. Fix: one-line check of the `executeGmCommand` body; if confirmed, call `logAdminAction` fire-and-forget.

**18. No ban-scope guard: self-ban and banning admins allowed.**
`apps/server/src/routes/admin.ts:213-232`. Fix: reject `target == actor`, require `admin` role to ban an `admin` (or record the choice in `DECISIONS.md`).

**19. Announcements marked sent with zero recipients.**
`adminRuntime.ts:93-102`, `routes/admin.ts:333-340` — `markSent` runs unconditionally; an announcement sent with nobody online is never redelivered. Fix: only `markSent` when `delivered > 0`, or flush pending on next join.

**20. Stealth semantics vs enemy players undefined.**
`playerSnapshots` (`:5574`) and `pvpActors.ts:18` exclude GM `invisible` but not stealth buffs; interest and `canPvpTarget` ignore stealth. If stealth should hide in PvP, gate views/targeting/swing candidates; otherwise document PvE-only (assassin stealth + Phase 8 PvP makes this urgent to decide).

**21. PvP rules matrix is unpinned by tests.**
`packages/shared/src/pvp.ts:51-54` — free-mode attacker can hit a kingdom-mode same-kingdom player who can't hit back; possibly correct per §9 but uncited and untested. PvP is the #1 false-bug-report generator. Fix: pin the full 3×3 matrix (+party/guild/safe-map) in `pvp.test.ts` now.

**22. Panel lacks position and bonus editors the API already supports.**
`PlayerActions.tsx:80-174` (no x/y despite `adminUpdateCharacterSchema` carrying them) and `:210-218` (`bonuses: []` hardcoded despite server allowing 5); §10.5 promises "edit … position" and "give item (with upgrade level and bonuses)". Fix: add the fields or explicitly descope in `DECISIONS.md`.

**23. Fresh-clone `pnpm dev` degrades silently.**
`scripts/dev-db.mjs` starts compose only for localhost, but the shipped `.env.example` default is `raspberrypi.local`; nothing documents the first-run migrate/seed sequence, so a fresh clone runs with `db:"unavailable"`. Fix: document the sequence; reconsider the default.

**24. Per-tick `pvpContext()` rebuilds are O(P²) under PvP chase.**
`MapRoom.ts:6064,6007,5073` each rebuild the actor map; chasers do it every tick; `playerSnapshots` (`:5574`) also calls `Date.now()` per player. Fix: build once per tick, hoist `now`.

**25. No per-command rate limit on DB-backed intents.**
`shopBuy`/`upgradeItem`/`moveItem` each trigger a transaction, bounded only by Colyseus `maxMessagesPerSecond`. Fix: small per-command cooldown or token bucket.
